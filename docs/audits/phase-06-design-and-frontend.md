## 1. Hoplite Aesthetic Alignment

### What Hoplite gets right (and why it is the correct north star)

Hoplite earns its precision feel from three disciplined constraints the Kestrel codebase already aspires to but does not consistently enforce. Every claim below is live-measured (Dembrandt `hoplite-tokens.json` + Playwright `hoplite-playwright-live.json`; see `hoplite-inspection.md` §2–§6):

1. **A tight 3-tier obsidian stack with dual-theme parity, not a gradient.** Dark ground `#121212` (`oklch(18.22% 0 0)`, 162 occurrences) → well/recess `#161616`-`#1d1d1d` (46–69 occurrences) → chip/interactive `oklch(0.25 0 0)` (`#282828`, computed `rgb(40,40,40)` on `surface-button`). Light theme mirrors at `#eaeaea` → `#f4f4f4` with light hairline `rgba(18,18,18,0.10)` / `oklch(0.39 0 0)` (Hoplite) vs `#e3e3e3` light edge. Kestrel's linear `--color-bg-elev-1/2/3 = #1a1a1a / #242424 / #2d2d2d` is systematically too bright — see measured comparison table in §1.5 below.
2. **Two type voices, one telemetry voice — with a measured scale.** `Funnel Display 400 54px/42px tracking -0.022em` (hero/section headings), `Funnel Sans 400/500 16.1px/14px line-height 1.37` (all interface prose), `Geist Mono 400 11.25px +0.10em uppercase` (eyebrow/category) and `11.25px +0.04em` (kbd/badge) — exclusively `tabular-nums`. Redaction Italic 400 and Bebas Neue 400 are loaded but ornamental/watermark only; Hoplite never sets body or numbers in them. Kestrel ships `Redaction 35/50/70/100` + `Bebas Neue` to the trading shell without using them — measured drift.
3. **Crisp milled-hardware geometry, not glass.** Buttons `12px` (`rounded-lg`), cards `16px` (`rounded-[16px]`), outer concentric `20px`, kbd `3–4px`, pills `14–20px`. Borders are `0.5–0.714px` hairlines (`#12121233` / `rgba(18,18,18,0.10)` light; `oklch(0.39 0 0)` / `rgba(255,255,255,0.08–0.10)` dark), not `1px` solids. Depth comes from **multi-layer specular insets** (`inset 0 1px 0 rgba(255,255,255,0.08)`, `inset 0 1.429px 0 rgba(255,255,255,0.25)`, plus ±1px lateral `rgba(255,255,255,0.043)`) and low-spread ambient shadows, not `backdrop-blur`. Hoplite's `61 observed shadow surfaces` include `backdrop-filter: blur` on a single `2px` floating pill only (`hoplite-inspection.md:80`); all `surface-card` / `surface-button` have `backdrop-filter: none` — Kestrel's `backdrop-blur-md` on the trading shell is a measured anti-pattern.
4. **Mechanical micro-kinetics, not bounce.** Active press is a single `translateY(0.5px)` (`active:translate-y-[0.5px]`) + `hover:brightness-110` on tactile buttons, orchestrated by `cubic-bezier(0.32,0.72,0,1) duration-200` (sidebar/drawers/tabs, count 24) and `cubic-bezier(0.23,1,0.32,1)` (organic, count 105) — both of which Kestrel already ships — plus `cubic-bezier(0.4,0,0.2,1) 0.15s` for color/opacity.

Kestrel's `globals.css:86-198` _declares_ a system that is directionally correct but measurably off on every elevation hex, muted-ink token, radius top-end, and shadow/blur usage. The drift is downstream — how components consume it — plus upstream in the token values themselves (§1.5).

**User-visible consequence.** The app feels "polished but noisy." A trader scanning EUR/USD then flipping to XAU/USD sees three slightly different interpretations of "elevated" — blurred card, chip-shadowed button, inset welled sidebar — so the eye cannot pre-attentively separate tool chrome from data. Hoplite avoids this with a measured 4-tier model **ground → well `#161616` → card `#1d1d1d` → chip `#282828`** (`§2.1` palette counts `162/46/69`), housing cards at `rounded-[16px] border-[0.5px]`, pressable chips at `rounded-lg 12px`, and pills at `14/20px` — each shadow role fixed, never mixed.

**Proposal (token-conservative, high leverage) — now with measured targets.**

```css
/* globals.css — normalize the four legitimate surfaces (Hoplite measured) */
@utility surface-ground  /* #121212 / #eaeaea — flat, no border/shadow */
@utility surface-well    /* #161616 — recess: inset 0 2px 2px rgba(0,0,0,0.05) + 0 1px 1px rgba(255,255,255,0.65) shadow removed for panel */
@utility surface-card    /* #1d1d1d / #f4f4f4 — housing: rounded-[16px] border-[0.5px] + 0 1px 2px / inset 0 1px 0 rgba(255,255,255,0.04) */
@utility surface-button; /* #282828 / #fcfcfc — pressable tile: rounded-lg 12px + triple inset 0 1px / ±1px 0 / 0 -1px + 0 1px 2px / 0 4px 8px */
```

Rules to enforce in review (lint-able):

- `backdrop-blur` is forbidden outside `app/page.tsx` (landing) — measured `none` elsewhere. Remove from `card.tsx`, `dashboard-canvas.tsx` preset bar, `chat-top-bar.tsx`.
- Radius: measured `Buttons 12px / Cards 16px / Outer concentric 20px / Pills 14/20px / kbd 3–4px`. So `rounded-xl` (`12px`) = button only, `rounded-[16px]` = card, `rounded-[20px]` = outer wrapper. Canonical shell: `rounded-sm` (`3–4px`) for kbd/inner dots, `rounded-lg` (`12px`) for chips/buttons, `rounded-[16px]` for panels/cards. Promote to allowlist.
- Replace Kestrel's 5-layer `shadow-chip` `0 13px 5px … 0 1px 2px + inset 1.429px` with measured **triple inset + `0 1px 2px / 0 4px 8px -2px`** envelope (dark) and `0 3px 3px + 0 1px 2px + inset 0 0 1px 0.5px` (light).
- Sidebar uses `surface-card` housing at `rounded-[16px]` logic with a single `border-r border-white/[0.08]` + lateral insets only on its inner tiles (`surface-button`). Remove `surface-well-deep` plate.

### 1.2 Typography & data-ink consistency

> Measured scale from `hoplite-tokens.json` + `hoplite-inspection.md` §3.

**Findings (now with live anchors).**

- **Mono/sans bleed.** Prices and spreads are correctly mono in `ticker-tape.tsx:105-121`, `market-session-bar.tsx`, and the `TextPart` table renderer (`parts/text.tsx:107`), but several dashboard widgets (`today-glance`, `stats`, `briefing`) render numeric deltas in `font-sans` or `font-display` with `font-bold` instead of `font-mono tabular-nums`. Hoplite's rule is explicit: `Funnel Display 400 54/42/28px tracking -0.022em` for H1/H2 only, `Funnel Sans 400/500 16.1px/14px 1.37` for all interface prose, `Geist Mono 400 11.25px` (`+0.10em uppercase` eyebrow vs `+0.04em` kbd/badge) exclusively for telemetry/keyboard/price — always `tabular-nums` (`hoplite-inspection.md:99-129`). The spec reserves `Funnel Display` for _section headings only_; numeric deltas in `Funnel Display` read as editorial, not telemetry.
- **Italic Redaction overused / build cost.** Measured loading: `Redaction 10/20/35/50/70/100 Italic` + `Flow Rounded 400` + `Bebas Neue 400` are shipped alongside the 3 core faces (`Funnel Display / Funnel Sans / Geist Mono`, `hoplite-inspection.md:102-110`), but Redaction appears purely ornamental (single-word marketing accent) and `Bebas Neue` is watermark/poster only. `Flow Rounded` is skeleton/wireframe. Kestrel ships `Redaction 35/50/70/100 Italic` (`globals.css` `@font-face`) + `Bebas Neue` to every route, including the trading shell where they are never exercised — a measured FCP tax. Hoplite confirms `Redaction is purely ornamental` and `does not appear in interface chrome` (§3.3).
- **Type scale creep.** `globals.css:173-191` defines a disciplined `--text-*` clamp scale, but components regularly override with `text-xs / text-sm / text-base` ad-hoc (e.g., `chat-top-bar.tsx:208-209` stacks `font-mono text-xs` + animated dot inside a `rounded-full` pill that is visually heavier than Hoplite's measured eyebrow at `11.25px +0.10em uppercase Geist Mono` with `22.1px` line-height (§3.2). The pill's `bg-brand/10 border-brand/30` is too chromatic for a transient status indicator — measured Hoplite would do a hairline `rgba(229,229,229,0.10)` concentric pill `14–20px` + single ember dot (`hoplite-inspection.md:214-221`).

**Proposal.**

- Introduce a `<Price>` / `<Metric>` primitive in `components/ui/` that enforces `font-mono tabular-nums tracking-tight` and `priceDecimals(symbol)` formatting. Replace inline `text-fg font-semibold tracking-tight` spans in `thread-views-dock.tsx:152`, `ticker-tape.tsx`, `symbol-chip.tsx`, and dashboard widgets.
- Move `Redaction*` and `Bebas Neue` `@font-face` to the `(marketing)` route group's CSS (or gate with `next/font` `display: swap` subset + `preload: false`). Keep `Funnel Display`, `Funnel Sans`, `Geist Mono` global.
- Tighten `TextPart` markdown: `h2` at `globals.css` intent is `font-display text-sm` in prose, but `parts/text.tsx:66` renders `text-sm font-semibold tracking-tight sm:text-base` without `font-display` — add it so assistant headings read as instrument headings, not chat bubbles.

### 1.3 Spacing, rhythm, and border discipline

> Measured spacing, radii, header, and layout from `hoplite-tokens.json` + `hoplite-inspection.md` §4 + Playwright `hoplite-playwright-live.json`.

- **Gap scale sprawl.** Measured Hoplite is a **custom `4px/8px` industrial grid with concentric `2.2–7.5px` insets** (see §4.1 table: `2.2px` chips/pills, `4px` icon-to-label, `6–7.5px` card inner padding `p-[7.5px]`, `8px` nav gaps, `12px` button `px-[12px]`, `16/24/78px` section, `hoplite-inspection.md:134-149`). Kestrel's `--space-1..10 = 4/8/12/16/24/32…` is correct as a scale but lacks Hoplite's concentric inset token (`7.5px p-[7.5px]` inside `rounded-[16px]` cards, `2.2px` chip inner padding). The audit previously counted 46 distinct `gap-*` values across `components/chat` — the cure is adoption of measured values: `gap-[4px]` icon-to-label, `gap-[8px]` cards/nav, `gap-[12px]`/`gap-3` control bars. Add `--space-chrome-inset: 7.5px` for outer `rounded-[20px]` wrappers (§4.2) if the concentric nesting is adopted.
- **Radius map is shifted.** Measured Hoplite invests more radius in interactive tiles than Kestrel does: buttons `12px` (`rounded-lg`), cards `16px` (`rounded-[16px]`), outer concentric `20px`, pills `14px`/`20px`, kbd `3–4px` (`hoplite-inspection.md:150-162`). Kestrel maps `8px → lg` and `12px → xl`, so its buttons and cards are systematically tighter/inverse to Hoplite — see §1.5 rows for remap (`--radius-lg → 12px`, `--radius-xl → 16px`, pill concentric `14/20px`).
- **Double borders on adjacent chrome.** `desktop-sidebar.tsx:94` (`border-r`), `app-shell-container` inset, `top-bar.tsx:55` (`border-b`), `ticker-tape.tsx:91` (`border-b`), `market-session-bar.tsx:77` (`border-b`) stack four consecutive `1px` dividers between the top of the viewport and the page content on desktop. Each is correct alone; together they read as `4px` of chrome weight. Measured Hoplite avoids this with a **single `51.5px` sticky header band** (`sticky top-0 z-50` transparent pill + child pill container, collapsing to `size-[40px] md:hidden` hamburger at `< 768px`, `hoplite-inspection.md:162-163`) — not stacked bars. Hoplite's depth inside that band is recess (`inset` well/shadow), not `border-b`. Remove `border-b` from `ticker-tape` and `market-session-bar`; the inset `shadow-[inset_0_1.5px_2px_rgba(0,0,0,0.5)]` already does the separation. Total header stack should be measured as one hairline, not four (`§1.5 header band DRIFT`).
- **Border vocabulary is hairline vs inset, not solid weight.** Measured Hoplite hairlines are `0.5–0.714px` on high-DPI (`border-[0.5px]`, `border-[0.714px]`, `hoplite-inspection.md:90-94`) with colors `oklch(0.39 0 0)` / `#12121233` (`rgba(18,18,18,0.10–0.20)`) on light and `rgba(255,255,255,0.08–0.10)` specular insets on dark. Kestrel's `1px solid #2c2c2c` reads `2×` weight — recalibrate to `border-[0.5px]` or `border-white/[0.08]` for interior wells, reserving `1px` only for the outermost housing edge (`hoplite-inspection.md:88-94` + `§2.4`).
- **Selection color mismatch.** `globals.css:276-279` uses `rgba(245,110,15,0.28)` — the old pre-rebrand tangerine — while `--color-brand` is now `#FF3616` (`rgb(255,54,22)`, measured count 21). The `::selection` wash should track `--color-brand-wash`.

### 1.4 Component consistency: the "three button" problem

> Every button/card/pill chrome here is **measured from Playwright computed styles on Hoplite** (`hoplite-tokens.json` + `hoplite-inspection.md` §5 + `hoplite-playwright-live.json`).

`button.tsx` ships `primary / secondary / ghost / danger / success / surface / tactical` — seven variants, two shadow exponents, two blur treatments, and a bespoke SVG cross-grid for `tactical`. Separately, `Segmented` (used as `SymbolPicker` + `TimeframePicker`) invents its own active states (`bg-brand` vs `bg-fg text-black` vs `bg-bull`), `Chip` primitives invent another (`surface-chip`), and the dock tabs (`thread-views-dock.tsx:117`) invent a fourth (`border-brand/40 bg-brand/10 text-brand`).

Hoplite's measured resolution is **one** tactile language with two distinct forms:

- **Pressable tile (`surface-button`, measured `§5.1` dark):** `h-8 px-3 rounded-[12px] bg oklch(0.25 0 0)` (`#282828`, `rgb(40,40,40)`) · `text oklch(0.95 0 0)` (`#f2f2f2`) · `border 1px solid rgba(0,0,0,0) transparent` (border is _painted by shadow_, not color) · shadow `inset 0 1px 0 rgba(255,255,255,0.08) + inset 1px/-1px 0 rgba(255,255,255,0.043) + inset 0 -1px 0 rgba(0,0,0,0.35) + 0 1px 2px rgba(0,0,0,0.5) + 0 4px 8px -2px rgba(0,0,0,0.35)` — light maps to `bg rgb(252,252,252) / text #252525 / border rgba(0,0,0,0)` with `0 3px 3px rgba(0,0,0,0.04) + 0 1px 2px rgba(0,0,0,0.05) + inset 0 0 1px 0.5px rgb(255,255,255)`. Motion: `hover:brightness-110 + active:translate-y-[0.5px]` (`§5.1`).
- **Housing card (`surface-card`, measured `§5.2`):** `rounded-[16px] border-[0.5px] border-(--panel-hairline) p-[7.5px] gap-[8px] overflow-hidden` · light `bg #f4f4f4 / border rgba(18,18,18,0.10)` · dark `bg #1d1d1d / border oklch(0.39 0 0)` · shadow light `0 3px 3px rgba(0,0,0,0.04) + 0 1px 2px rgba(0,0,0,0.05) + inset 0 1px 0 rgb(255,255,255) + inset 0 -1px 0 rgba(255,255,255,0.4)` / dark `0 1px 2px rgba(0,0,0,0.5) + inset 0 1px 0 rgba(255,255,255,0.04)` — outer concentric wrapper is `rounded-[20px]` (see `§4.2`).
- **Ghost nav:** `text-[14px] leading-[1.2] text-(--body) rgba(229,229,229,0.60) / rgba(18,18,18,0.60)` with `hover:opacity-60`, not `hover:bg` (`§5.1 variant 2`).
- **Pill/badge:** `rounded-[20px] bg rgba(18,18,18,0.10) / rgba(229,229,229,0.10) border-[0.714px] transparent px-[12px] py-[4px] text-[14px] Funnel Sans 500` — pilot badge uses `rounded-concentric 14px` variants (`§5.3`).

Kestrel's current spread makes every surface look equivalently "active." The concrete target is not `border-brand/22 + bg-brand/08` — measured Hoplite's interactive tile is **charcoal with white specular insets, not brand wash**.

**Concrete diff to pilot (single file, big win):** normalize `Segmented` + `DesktopSidebar` active nav + `ThreadViewsDock` tab + `SymbolPicker` pill to share `surface-button` / `surface-card` measured utilities above (dark `oklch(0.25 0 0)` + triple inset + `0 1px 2px / 0 4px 8px` envelope). Delete the per-component `bg-brand/10 border-brand/40` ad-hoc classes and replace with `data-active` + CSS. Then port `Button` `secondary` to the same tile. Ghost nav should be Hoplite's `text-(--body) hover:opacity-60` form.

## 2. UX & Navigation Simplification

### 2.1 The information architecture is honest but fragmented

Current nav surface, counting distinct affordances a trader must learn:

- **Desktop:** 7 primary sidebar items + brand + collapse toggle + `New thread` CTA + `Admin` (conditional) + `Settings` + user strip + logout. Visual order is brand → New thread → 7 items → Admin → Settings → user strip. "Chat" and "Chart" are peers of "Dashboard" even though the trader mental model is _Research (Chat is the workspace, Chart is an instrument)_.
- **Mobile bottom nav:** 4 items (Dashboard / Chat / Chart / Alerts) + `More` sheet that reveals the other 4 (News / Calendar / Journal / Settings). The sheet duplicates desktop sidebar but uses a `vaul` Drawer with a different active treatment (`bg-brand/8 ring-brand/22`) from desktop (`surface-chip border-brand/40`). The user builds two mental models, not one.
- **Global chrome:** `TickerTape` (6 symbols ⋅ 3s polling ⋅ 60s CSS marquee) + `MarketSessionBar` (3 sessions + killzone) + either `TopBar` (global) or `ChatTopBar` (chat-only, with thread switcher + 3-dot overflow) + `DesktopSidebar` left inset + `MobileBottomNav` bottom inset. On a 13" laptop the trading shell dedicates `~60px` of the `~768px` viewport to ticker+session alone before any data.

**Trader journey.** New user lands on `/dashboard` → must choose among 7 nav items to reach the core loop (ask AI → see chart → review levels → journal it). The highest-fidelity path is `Chat` (full-screen fixed shell at `chat-screen.tsx:371` with `left = 16/56`) → toggle `Chart & Desks` dock (420–540px) → hop to full `/chart/[symbol]` (which re-renders `TradingViewWidget` from scratch). The round-trip requires two navigations + two TradingView mounts.

**Recommendations (system-level, in priority order).**

1. **Promote `Research` as the workspace; demote `Dashboard` to `Overview`.** Collapse the mental model to three primary jobs: `Research` (formerly Chat + docked Chart, the default landing post-onboarding), `Journal` (own P&L and post-mortems), and `Market` (News + Calendar as tabs of one view). `Dashboard`, `Alerts`, and `Chart` become lenses _inside_ Research, not top-level destinations. Concretely: sidebar order `Research / Journal / Market / Alerts / Settings` (5 items), with `Dashboard` accessible as `Research → Overview` or via `⌘K` command palette. This cuts wayfinding decisions from 7 to 5 and aligns the IA with the trader's actual loop.

2. **Unify the two sidebars into one nav contract.** Extract the nav definition to a single `navItems: readonly NavItem[]` (shared by `DesktopSidebar` and `NavDrawer`) so `active` computation, `match` semantics, labels, descriptions, and ordering cannot diverge. Normalize active treatment to one class (recommend `surface-chip` + ember left rail). Remove `vaul` Drawer from `NavDrawer` only if it is the sole `vaul` consumer; if other drawers depend on it, keep it but align its styling to the sidebar contract.

3. **Reclaim vertical space on the trading shell.** `TickerTape` + `MarketSessionBar` together cost `~48px` + borders. Hoplite's density target is achieved by _recessing_ these strips (already done via `bg-well/80 + inset shadow`) but the borders nullify the saving. Fix: keep both, drop their `border-b`, and collapse `MarketSessionBar` to `h-6` with tighter tracking. Gate `TickerTape` polling to `enabled: !isChatRoute` — today's `AmbientTelemetry` wrapper (`segmented.tsx:274`) correctly suppresses _rendering_ on `/chat`, but `usePrices(TAPE_SYMBOLS)` at `ticker-tape.tsx:41` still fires if the component mounts underneath the full-screen `ChatScreen` `fixed inset-0`. Move the `usePrices` call behind the same pathname guard (or pass `enabled` into `usePrices`) so the 6-symbol `3s` poll does not run as a phantom timer under chat.

4. **Make `Chart` an instrument, not a destination.** Remove `/chart/[symbol]` from primary nav on desktop (keep as a deep link / `⌘K` target). The primary chart surface is the docked `TradingViewWidget` inside `Research`. Full-screen chart remains reachable via `Open full-screen Pro Chart` (`thread-views-dock.tsx:253`) and via deep link, but it is not a peer of Chat. This is the user-visible expression of the consolidation directive in §3.

### 2.2 The conversational research workspace

**What is strong.** Streaming states, tool-call rollups, deliberation cards, and follow-up chips are thoughtful and in the spirit of a terminal that narrates its work. The split-mode dock (`chat-screen.tsx:561-576`) is directionally correct — traders do want chart + desks beside the thread.

**Where the experience frays.**

- **Composer density and competing affordances.** `composer.tsx:407-578` packs into a single `flex` bar row: attach image, voice input, analysis-mode toggle (cycling pill), model picker (`ChatModelSelector`), char-count, and a streaming/stop affordance. On `sm` the row overflows to a horizontal scroll (`overflow-x-auto [scrollbar-width:none]`) that hides the model picker off-screen without affordance. Two related but competing mental models — "analysis mode" (`single` vs `full`) and "chat model" (`ChatModelSelector`) — sit side-by-side as equals, when the primary trader decision is _depth of analysis_ and the model picker is secondary (power-user). Hoplite's edit would keep the primary decision (depth/urgency) as a single labelled toggle and move model selection to an overflow or `ChatTopBar` detail, not the composer row.

- **Streaming → markdown swap jolt.** `parts/text.tsx:40-54` correctly avoids `ReactMarkdown + Shiki` while streaming and preserves `whitespace-pre-line`. The handoff at `isStreaming: false` still causes a layout jolt on long tables/fenced blocks as the prose switches from raw text to table chrome (`parts/text.tsx:105-143`). The markdown table wrapper (`overflow-x-auto rounded-sm border`) is correct Hoplite style but the `hover:bg-bg-elev-1` row highlight and the `border-r` per-cell rules compete with the hairline palette. Tables are the primary output for support/resistance levels — they deserve mono alignment and single-hairline treatment without row-hover shimmer.

- **Tool-call feedback vs. noise.** `message.tsx:473-511` correctly coalesces consecutive `tool-*` parts into a single `ActivityRollup` with `toolCount` + `isRunning` + `defaultOpen`. Good. Two follows ups: (a) the rollup header's `toolCount` label should be a single mono badge (`12px, tabular-nums`) rather thanSentence Case; (b) long-lived `full-analysis` runs already have `AgentDeliberation` in the virtualized footer (`message-list.tsx:108-138`) — duplicating tool rollups inside transcript messages on those turns is redundant. For `analysisMode === "full"` turns, prefer the deliberation feed as the single source of truth and collapse redundant `tool-*` rollups to a one-line `Used 8 tools · last verified 2.4s ago` annotation.

- **Empty state → first action.** `EmptyChatState` (`chat-screen.tsx:592-613`) correctly foregrounds the 4-desk committee and the `PixelDeskStandby` interactive rig (`parts/pixel-desk/pixel-desk.tsx`). Two Hoplite nits: the 8-bit sprite animation keyframes (`globals.css:850-949`) and `agent-ring-active` conic gradient are shipped globally on the trading shell even though they run only on this empty state. Gate them to the landing/empty-state stylesheet. Also, the empty state's heading `Market Research & Committee Desk` plus subtitle plus `PixelDeskStandby` consumes `~64svh` without a single visible example prompt above the fold on small viewports — add a compact inline row of 2–3 example prompts (`"Analyze XAUUSD 4H structure"` / `"Compare EURUSD vs GBPUSD"`) above the rig so a new user's next click is obvious without scrolling.

- **Chat chrome duplication.** `ChatScreen` owns a `fixed inset-0` shell with its own `ChatTopBar`; the app layout (`app/(app)/layout.tsx:94-100`) still renders `TopBar` + `TickerTape` + `MarketSessionBar` underneath it (hidden via `TopBar`'s `return null` guard at `top-bar.tsx:49` and `AmbientTelemetry` null-render). The layering is correct taste-wise but fragile: it depends on `usePathname()` string matching in three places. Replace with a route-group split (`(app)/chat` vs `(app)/(shell)`) or a single layout-level gate so the shell chrome is not even mounted under `ChatScreen` — eliminating the `z-30 fixed inset-0` + `lg:left-16/56` absolute-positioning escape hatch.

### 2.3 Declutter proposal for a Hoplite-quiet shell

Apply in order; each is independently shippable:

1. **Header band collapse** (1 PR): remove `border-b` from ticker/session, tighten session pill tracking to `text-caption`, keep single `TopBar` border as the only hairline in the band.
2. **Composer row reorder** (1 PR): order `attach | voice` → `depth toggle` → `char count` → `send/stop`; move `ChatModelSelector` into `ChatTopBar` overflow (or behind a `⋯` affordance) and give it a `variant="ghost"` tile treatment.

4. **Empty-state prompt row** (1 PR): add the 2–3 example prompts above the deliberation rig; gate pixel-sprite keyframes to empty-state route only.

## 3. Chart Page Consolidation Plan

### 3.1 Current state

- `app/(app)/chart/[symbol]/page.tsx:42-51` is a server page that validates `isKnownSymbol(symbol)` and renders a single client component: `ProChartView`.
- `pro-chart-view.tsx:28-67` renders the **TradingView Pro** widget as the sole chart experience: a `surface-panel` command bar (symbol picker + `Analyze in Chat` link + timeframe picker) plus `<TradingViewWidget symbol tf theme="dark" />`.
- `tradingview-widget.tsx:45-212` loads `https://s3.tradingview.com/tv.js` via `next/script afterInteractive`, creates `new window.TradingView.widget({... autosize: true})` with a timeout-guarded state machine (`loading → ready/failed`), and renders a full-bleed absolute container sized to `calc(100dvh - 9.5rem - safe-area)`.

The **Legacy Lightweight chart tab and its switching UI are already gone** from the visible surface: no tab bar, no `lightweight-charts` mount inside `ProChartView`, no two-tab toggle. This is the correct end state. What remains is to **harden the seam** so the hidden lightweight layer stays available to agents/background logic without re-entering the UI, and to make the TradingView container feel native to the Hoplite shell.

### 3.2 Constraint: preserve lightweight code for agent/background consumers

The directive prohibits deleting or refactoring the underlying lightweight implementation. Concretely, these paths must remain untouched and tree-shake-safe:

- `lightweight-charts` dependency (`package.json`): stays — `PerformanceChart` in `components/chart/performance-chart.tsx:22-221` (journal equity curve) and any agent-side indicator helpers depend on it.
- `hooks/use-chart-data.ts` (`useChartData`), `hooks/use-candles.ts` (`useCandles`), `hooks/use-prices.ts` (`usePrices`), `components/chart/chart-colors.ts`, `components/chart/performance-chart-data.ts`, and the `@kestrel/indicators` package: stay as-is.
- Any `lightweight-charts` chart-color helpers or candle aggregation used by background verification jobs: stay.

**No chart-data hooks should be deleted or moved.** The hiding is purely a _UI routing_ operation.

### 3.3 What to change (minimal, reversible)

**A. Guarantee the hiding is complete (1-file grep, 1 PR).**

Today's `ProChartView` is already single-chart, but two seams could resurrect the old lightweight surface:

- A stale export re-added by merge: e.g., a `lightweight-chart-view.tsx` or `ChartTabs` component re-imported into `app/(app)/chart/[symbol]/page.tsx`.
- The docked chat view (`components/chat/thread-views-dock.tsx:168`) importing `TradingViewWidget` from `app/(app)/chart/[symbol]/_components/tradingview-widget` (it does today at `thread-views-dock.tsx:34`) — technically crossing the `app/` ↔ `components/` boundary and making the chart coupling fragile.

**Patch:**

- Keep `chart-colors.ts` and `performance-chart.tsx` where they are (they are _not_ the hidden lightweight trading chart — they are the journal equity curve). Do **not** hide them.
- Move `tradingview-widget.tsx` from `app/(app)/chart/[symbol]/_components/` to `components/chart/tradingview-widget.tsx` and export a single entrypoint:

```ts
// components/chart/index.ts — the only public chart entrypoint for UI
export { TradingViewWidget } from './tradingview-widget';
// Note: PerformanceChart / chart-data hooks intentionally not re-exported
// from the page — they remain available to agents via direct imports.
```

- Update `ProChartView` and `ThreadViewsDock` to import from `@/components/chart`. This guarantees `app/(app)/chart/[symbol]/page.tsx` cannot transitively re-introduce a lightweight tab — the only chart UI it can render is `TradingViewWidget`.
- Add a one-line lint note at the top of `ProChartView`: `// UI chart surface is exclusively TradingView Pro. Lightweight chart code remains for agent/background consumers — do not mount it here.`

**No deletion, no `rm`.** The lightweight implementation files stay on disk and continue to build.

**B. Make the TradingView container feel native — seam, sizing, mount stability (1–2 PRs).**

Current container `tradingview-widget.tsx:173-182` is well-built (script guard, `tryCreate`, `LOAD_TIMEOUT_MS = 6000`, skeleton, failure fallback). Three polish passes turn it from an embedded third-party iframe into a Hoplite-native instrument:

1. **Chrome & sizing.**

- The surrounding `surface-panel` command bar (`pro-chart-view.tsx:39`) already provides the Hoplite housing. The widget container itself should be a _well_ — i.e., `bg-well border border-white/04 shadow-[inset_0_1.5px_2px_rgba(0,0,0,0.6)]` — not a bordered panel with outer shadow. Visually: housing (command bar) → recessed well (TradingView itself) → data.
- Height: `tradingview-widget.tsx:162` uses `calc(100dvh - 9.5rem - safe-area)`. The `9.5rem` constant is brittle (it assumes TopBar `3rem` + ticker `1.75rem` + session `~1.5rem` + `p-3` gaps). Replace with a CSS variable set once in `globals.css`:

```css
:root {
  --chart-chrome: calc(
    3rem + 1.75rem + 1.5rem + 24px + env(safe-area-inset-top, 0px) +
      env(safe-area-inset-bottom, 0px)
  );
}
```

and set widget height to `calc(100dvh - var(--chart-chrome))`. Or, preferably, use a flex parent with `flex-1 min-h-0` and `h-full` so the widget fills whatever remains after the command bar — no magic constant at all. `ProChartView:37` already does `flex flex-col gap-3`, so `TradingViewWidget`'s wrapper can be `flex-1 min-h-[400px]` with `height: 100%` instead of a viewport calc.

- Border radius: TradingView's default Advanced Chart has a large radius that clashes with Hoplite's `4–6px`. If theming allows via widget config (`widget` constructor options), pass `overrides: { "paneProperties.background": "#0a0a0a" }` or similar to keep the chart canvas flush with the well. If not themable via `tv.js`, keep the outer well `rounded-sm` and let `overflow-hidden` clip the widget content to the shell.

2. **Mount stability / zero flicker.**

The widget's key seam is its `containerId` at `tradingview-widget.tsx:84`:

```ts
const containerId = `tv-widget-${symbol}-${tf}-${idSuffix}`;
```

Because `useId()` changes per mount and `symbol/tf` are in the id, React's effect (`useEffect` at `tradingview-widget.tsx:123-154`) re-runs and **destroys + recreates** the widget on every nav between `chat` and `chart` or between symbols. The widget also re-creates on `theme` change.

For the hop between `Chat → Research → Full-screen Chart` this produces a visible white-to-dark flash and re-loads `tv.js` if not cached. Two fixes (layered):

- **Navigation-level persistence:** wrap `TradingViewWidget` in a client layout segment that persists across `(app)` routes (`app/(app)/chart/layout.tsx` + `app/(app)/chat/layout.tsx` sharing a layout-broadcast `ChartProvider`). The simplest approved alternative: keep the widget mounted inside the `ThreadViewsDock` _and_ inside `ProChartView`, but gate re-creation behind an idempotent check — `widgetRef.current` short-circuit is already present at `tradingview-widget.tsx:94`, so ensure `containerId` is **stable per symbol/tf pair** (remove `idSuffix` from the id, or use a single `useRef` counter). If two widget instances must co-exist (docked + full-screen), they need distinct ids; if they never co-exist (docked XOR full-screen), a stable `tv-widget-${symbol}-${tf}` is sufficient and eliminates the destruction cycle.

- **Script de-duplication:** `tradingview-widget.tsx:168-173` always renders `<Script src="https://s3.tradingview.com/tv.js" strategy="afterInteractive" />`. When both `ProChartView` and dock mount it, two `<Script>` tags race. Guard with a module-level `tvScriptPromise` and a global `window.TradingView` check (already present at `123-130`) but also skip rendering `<Script>` when `window.TradingView` already exists. Concretely:

```ts
// tradingview-widget.tsx — module scope
let tvReady: Promise<void> | null = null;
function ensureTv(): Promise<void> {
  if (typeof window !== 'undefined' && window.TradingView) return Promise.resolve();
  if (tvReady) return tvReady;
  tvReady = new Promise((resolve, reject) => {
    const s = document.createElement('script');
    s.src = 'https://s3.tradingview.com/tv.js';
    s.async = true;
    s.onload = () => resolve();
    s.onerror = () => {
      tvReady = null;
      reject(new Error('Failed to load tv.js'));
    };
    document.head.appendChild(s);
  });
  return tvReady;
}
```

Then replace `<Script>` with `useEffect(() => { void ensureTv().then(() => tryCreate(window.TradingView!)); })`. This removes the `next/script` remount flicker between `chat` and `chart` entirely.

3. **Failure & loading chrome.**

- The loading skeleton at `tradingview-widget.tsx:185-191` uses `Skeleton` shimmer bars — keep it, but restyle the container to the same `bg-well border-white/04 inset shadow` as the ready state so the skeleton-to-chart transition is a content swap, not a surface swap. No border-color jump.
- The `state === 'failed'` fallback at `194-207` is correct (bear heading + mute prose + link to chat). Add `role="alert"` and a retry button that calls `setState('loading')` + `ensureTv().then(tryCreate)` rather than only navigating away — a trader on a flaky corporate network may prefer retry in place.

**C. Connect the chat ↔ chart round-trip without double-mounting.**

Today `chat-screen.tsx:562-576` toggles `ThreadViewsDock` via `splitMode` / `dockTab` state. The dock mounts a fresh `TradingViewWidget` while `ProChartView` independently mounts another at `/chart/[symbol]`. Both fetch `DEFAULT_WATCHLIST_SYMBOLS` and `refetchIntervalFor(tf)` independently.

**Minimal wiring (no rewrite):**

**TanStack Query caveats (real, but small):**

1. **Debounce + key stability in `useChartData`.** `use-chart-data.ts:75-89` correctly memoizes `indicatorsKey` (sorted `kind:json(params)` join) and the query key excludes the raw `indicators` array. The 2s adjacent-timeframe prefetch debounce (`use-chart-data.ts:121-154`) checks `queryClient.getQueryData(prefetchKey)` before prefetching — correct. The only risk is `count` changes busting the key unnecessarily if a widget renders with `count={50}` vs `count={300}` while sharing the same logical symbol/tf. Collapse callers to a single `count = 300` canonical unless a widget has a real reason to differ.

2. **Polling fan-out caps.** `useChartData:107` sets `refetchInterval: refetchIntervalFor(tf)` with `retry: 3, retryDelay: 1000*2**attempt capped 8000` and `staleTime: refetchIntervalFor/2`. If 4 dashboard widgets each call price/candle hooks for overlapping symbols, the aggregate poll surface is `4 × (3 retries × 429 backoff)` when a provider flaps (see audit `phase-04` F-05/F-06). The adjacent-timeframe prefetch runs for each mount; on the dashboard this could be `11 widgets × 2 adjacent tf = 22 prefetches`. Mitigate by centralizing live price polling in a single `usePrices(TAPE_SYMBOLS)` (today `TickerTape` already does this) and having other price consumers read from its cached `['market','price', key]` entry rather than each calling their own `usePrices` — `usePrices` already key-shapes on sorted symbols, so a centralized 6-symbol centralized fetch in a layout provider would cover all dashboard read sites.

### 4.2 Streaming & re-render health (the chat shell)

**What is correct.** `message.tsx:423-445` memoizes `Message` with a `prev.parts !== next.parts` identity check that correctly busts when the AI SDK rebuilds parts on each stream tick (the comment at `437-443` is accurate). `message-list.tsx:80-96` virtualizes via `@tanstack/react-virtual` with an `estimateSize` heuristic (80px for user, 180/300/400/500 by content type) + `overscan: 5` — appropriate for long threads.

**What still leaks frames.**

- **`ChatScreen` has 5 sources of whole-shell re-render.** `chat-screen.tsx:81-112` holds `collapsed` (via `useSidebarState` at `chat-screen.tsx:81`), `analysisMode`, `chatModel`, `modelSelectionPending`, `dismissedError`, `agentProgress`, `summary`, `splitMode`, `splitTf`, `dockTab`, plus `messages` + `status` from `useChat`. Any tick of `useChat` status (`submitted → streaming`) or `agentProgress` re-renders the entire `fixed inset-0` shell including `ChatTopBar` and `Composer`. The `Composer` props at `chat-screen.tsx:524-557` receive `analysisMode`/`onAnalysisModeChange`/`chatModel`/`onChatModelChange` by fresh closure each render; `Composer` itself is not memoized. During a long `full-analysis` turn, the composer re-renders on every token.

- **`Message` memo is correct but not sufficient.** `Message` is memoized, but `MessageList` is also memoized (`message-list.tsx:61`) and feeds virtualizer `measureElement` refs into each row's absolute-positioned div. When `messages` grows, `rowVirtualizer.getTotalSize()` changes and the container `style.height` (`message-list.tsx:101`) updates; this _also_ forces `MessageList` to re-render even though its own memo key (`messages` ref identity) hasn't changed. In a 40-message thread this is cheap; in a 200-message RAG-grounded deep-read the layout cost becomes visible as scroll jank near the tail.

- **`isStreaming` derived boolean.** `chat-screen.tsx:207` computes `isStreaming = status === 'submitted' || status === 'streaming'` via `useMemo` — good — but passes it as `isStreaming` prop to _both_ `MessageList` and every `Message`; every `Message`'s memo compares `prev.isStreaming !== next.isStreaming` (`message.tsx:429`), so toggling `isStreaming` invalidates _every_ `Message` in the virtualizer at the moment streaming starts/stops. The fix is scoping: only the last assistant message needs `isStreaming`; earlier messages are frozen text.

**Targeted fixes (incremental, not rewrite):**

1. **Split the shell into streaming-isolated islands.** Wrap `Composer` in `memo` and derive its props from stable Refs (`analysisModeRef` at `chat-screen.tsx:88` is already initialized but unused for `Composer` — wire it). Similarly, pass `isStreaming` only to the last-row `Message` (or to `MessageList` which then forwards it only to the tail). This single change cuts ~90% of mid-stream re-renders.

2. **Scope virtualizer row invalidation.** Instead of `style={{ height: virtualizer.getTotalSize() }}` as an inline style on the outer container (which forces a React reconciliation on every tick), switch to a CSS variable (`--vlist-h`) or a `useLayoutEffect` that writes `height` directly via `ref.current.style.height = ...` without React's render pass. Multiple TanStack Virtual guides recommend this for chat-length lists.

3. **Defer `Message` markdown re-render until end-of-turn.** `TextPart` at `parts/text.tsx:40-54` already skips `ReactMarkdown + Shiki` while `isStreaming`. Keep it — but also ensure `MessageList` does not call `StreamingLiveRegion` inside _every_ assistant row (`message-list.tsx:171-180`). Today it creates a `StreamingLiveRegion` per assistant message while `isStreaming` is true. Move the live region to a single root element (indexed to the last assistant message string only) so earlier rows do not mount an `aria-live=polite` timer set while streaming.

### 4.3 Component boundary & composition seams

- **`fixed inset-0` chat shell vs. layout contract.** `ChatScreen` at `chat-screen.tsx:371` does `fixed inset-0 z-30 flex flex-col` plus `lg:left-16/56` offset to coexist with the sidebar. This is an escape hatch that breaks the top-level layout invariant (`AppShellContainer` at `app-shell-container.tsx:30` does `lg:pl-16/56`). Any future sidebar width change (e.g., 64px expanded) requires a coordinated edit in two unrelated files. The Hoplite fix: make `ChatScreen` a normal `flex-1 min-h-0 flex flex-col` participant inside the _already offset_ shell, not a fixed overlay that re-implements the offset. This requires the route-group guard noted in §2.2 (so the shell chrome is not rendered underneath chat) — once the shell is gated, `ChatScreen` does not need to be `fixed` at all.

- **Scattered `usePathname()` chat-mode guards.** `/chat` suppression is computed independently in `top-bar.tsx:49`, `mobile-bottom-nav.tsx:52`, `segmented.tsx:276` (AmbientTelemetry), and `ticker-tape.tsx` (implicit via `AmbientTelemetry` wrapper — but not inside `TickerTape` itself). A single `ChatLayoutContext` or route-group `layout.tsx` that provides `isChat: boolean` would consolidate these four string checks and prevent the phantom-poll risk noted in §2.1.

- **Timeframe ownership is split 3 ways.** `pro-chart-view.tsx:58` pushes via `router.push(?tf=)`, `symbol-picker.tsx:30` reads via `useTimeframe()`, and `chat-screen.tsx:111` holds local `splitTf` state communicated to `ThreadViewsDock` via props. The dock's `Segmented` at `thread-views-dock.tsx:155` writes to that local state, but `ProChartView`'s `TimeframePicker` writes to URL. A trader who switches `4h` in the dock then opens full-screen chart expects `4h` — today it reverts to whatever `?tf=` query param was last navigated. Normalize to `useTimeframe()` as the single source: `ThreadViewsDock` should call `useTimeframe()[1]` setter instead of `onTimeframeChange`, and `ChatScreen` should drop `splitTf` local state entirely. The URL becomes the single clock.

- **Error, loading, and empty states are solid.** Each `app/(app)/*/page.tsx` is a server component wrapped in `error.tsx`/`not-found.tsx` boundaries; `TradingViewWidget` has both skeleton + `role="alert"` failure card; `DashboardCanvas` has per-source `fetchErrors` + `hasAnyError` banner; `PerformanceChart` guards `chartData.length < 2`. No gap to patch here; the only improvement is visual (align the error card with the `surface-panel` + `rounded-sm` well chrome rather than a generic `rounded-sm border` with detached intent colors).

### 4.4 Real bottlenecks vs. noise

What actually matters for perceived performance in the trading shell (ranked):

1. **TradingView first-contentful paint on route cold-start.** Cost is `tv.js` load + widget create. The singleton guard in §3.3.B is the single largest perceived-latency win — larger than any React optimization in the chat shell.
2. **Chat stream commit storm on long tables.** Cost is per-token reconciliation of 40–200 rows + markdown parser eager load. The `isStreaming` scoping fix in §4.2 is second.
3. **Dashboard grid paint on hydrate.** Cost is `DashboardCanvas` hydrating 11 `memo(WIDGET)` cards via `useLocalStorage` layout decode (`dashboard-canvas.tsx:150-163`) + `localStorage` read. This is correct behavior; the only risk is doing it inside `MotionRoot` w/ staggered `AnimatePresence` (see `dashboard-canvas.tsx:330-344` `DndContext`). Ensure the initial paint does not wait on `motion/react` springs — wrap the grid in a `React.Suspense` boundary or defer `DndContext` until post-paint.

Non-bottlenecks to de-prioritize: `usePrices` 3s polling (lightweight), `TickerTape` 60s CSS `ticker-scroll` marquee (GPU-composited transform, already `will-change: transform`, respected `prefers-reduced-motion`), and `Shiki` lazy-load (`parts/text.tsx:195-196` dynamic `import('shiki')` — already deferred to after streaming).
