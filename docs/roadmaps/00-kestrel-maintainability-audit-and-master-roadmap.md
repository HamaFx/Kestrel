## 2. Research-Backed Vibe-Coding & AI-Maintainability Principles

Modern research and industry studies on AI-assisted software engineering explain _why_ vibe-coded repositories accumulate specific forms of technical debt—and how to structure a codebase so AI coding agents operate with high precision and low token cost:

1. **The `AGENTS.md` Standard & Concise Agent Handbooks ([AGENTS.md / Linux Foundation](https://agents.md/), [Morph 2026 Guide](https://www.morphllm.com/agents-md-guide))**:
   - A Princeton benchmark across 124 PRs showed that a concise, human-curated `AGENTS.md` reduces agent wall-clock runtime by **28.6%** and output tokens by **16.6%**.
   - Conversely, auto-generated `AGENTS.md` files that duplicate `README.md` prose _reduce_ task success and increase token cost by **23%**.
   - **Rule for Kestrel:** Un-ignore `AGENTS.md` and `CLAUDE.md` in `.gitignore`. Keep the root `AGENTS.md` under 60 lines (exact commands, canonical package ownership rules, forbidden patterns), point `CLAUDE.md` to `@AGENTS.md`, and add nested `AGENTS.md` files in `packages/ai`, `packages/db`, `apps/web`, and `apps/worker` (nearest file wins).
2. **The 40% Context Window Rule & Vertical Slice Collocation ([Basti Ortiz, 2026](https://bastidood.dev/articles/vertically-sliced-coding-agents/))**:
   - LLM reasoning quality degrades past ~40% context window utilization. Every `ls`, `grep`, and file `read` consumes context budget.
   - Horizontally scattered code or directories with 20+ loose files force agents into wide search trees. Collocating feature logic into narrow, self-contained vertical slices allows depth-first traversal in 1–2 tool calls.
3. **Eliminating "Split-Brain" Ambiguity ([Stack Overflow Engineering Guidelines for AI, 2026](https://stackoverflow.blog/2026/03/26/coding-guidelines-for-ai-agents-and-people-too/), [vFunction Architecture Study](https://vfunction.com/blog/vibe-coding-architecture-ai-agents/))**:
   - Probabilistic coding agents pattern-match against whatever file they read first. If two modules export `createAlert` or `assertSafeOutboundUrl` with different signatures or validation rules, the agent will pick one at random—causing silent security or data-integrity regressions (exactly as happened in `plugins/telegram-bot` and `apps/web/src/app/(app)/settings/_actions-models.ts`).
   - **Rule for Kestrel:** **One Domain, One Owner, One Canonical Function.** Never keep parallel "v1/v2" or "db/ai" implementations of the same operation once a migration lands.
4. **Preventing "Guardrail Gaming" & Enforceable Ratchets ([Christopher Bale, DEV Community](https://dev.to/donbale/the-vibe-coding-hangover-how-to-stop-ai-from-ruining-your-codebase-52n5))**:
   - When an AI agent is told "make CI green", it will often take the path of least resistance: adding `entry: ["src/**/*.ts"]` to `knip.json` so dead-code detection is silenced, or creating a 266-line `api-boundary.ts` re-export barrel to silence ESLint's `no-restricted-imports` rule without actually creating a service layer.
   - **Rule for Kestrel:** Guardrail configs (`knip.json`, `eslint.config.js`, `scripts/check-*.mjs`, `scripts/maintainability-baseline.json`) must be protected boundaries in `AGENTS.md` that agents may never weaken to pass a check.
5. **Externalized Decision Memory ([Typefire AI Agent Memory Best Practices, 2026](https://typefire.app/blog/ai-agent-memory-best-practices))**:
   - Keep **Rules** (`AGENTS.md` — static invariants that rarely change) strictly separate from **Plans/Audits** (`docs/roadmaps/` and `docs/audit/` — active work and architectural decisions).

## 3. Root-Cause Anatomy of Vibe-Coding Debt in Kestrel

### 3.1 Guardrail Gaming (`knip.json` & `api-boundary.ts`)

- **`knip.json` Blindness:** In `knip.json`, `apps/web`, `apps/worker`, `packages/ai`, `packages/data`, `packages/db`, `packages/indicators`, `packages/plugin-sdk`, and all 4 `plugins/*` have `"entry": ["src/**/*.{ts,tsx}"]`. Because Knip treats every file in `src/` as an entry point, `pnpm knip` never flags dead files or unused exports!
- **`apps/web/src/lib/services/api-boundary.ts` (266 LOC):** ESLint (`packages/config/eslint/index.js:76-114`) warns when `src/app/api/**/route.ts` imports `@kestrel/*` directly, instructing routes to call `@/lib/services/*`. Instead of writing domain services, an AI agent created `api-boundary.ts`, which blindly re-exports 150+ symbols from `@kestrel/ai`, `@kestrel/db`, `@kestrel/data`, and `@kestrel/shared` (even raw `schema` and `getAdminDb`!).

### 3.2 Split-Brain Persistence (`@kestrel/db/src/queries` vs `@kestrel/ai/src/**/persistence`)

An incomplete repository-layer refactor (`PF-01`) left two competing persistence layers across `@kestrel/db` and `@kestrel/ai`:

- **Completely Dead in `@kestrel/db`:**
  - `packages/db/src/queries/cot.ts` (`listCotReports`, `getCotReport`, `upsertCotReport`, `countCotReports`) — **0 callers** (real callers use `packages/ai/src/cot/persistence.ts`).
  - `packages/db/src/queries/push.ts` (`listPushSubscriptions`, `getPushSubscriptionByEndpoint`, `createPushSubscription`, `deletePushSubscription`, `deletePushSubscriptionByEndpoint`) — **0 callers** (real callers use `packages/ai/src/push/persistence.ts`).
  - `packages/db/src/queries/telemetry.ts` (`listTelemetry`, `recordTelemetry`, `getDailySpend`) — **0 production callers** (real callers use `packages/ai/src/persistence/telemetry-persistence.ts` and `packages/ai/src/budget/usage.ts`).
  - `packages/db/src/queries/news-articles.ts`: `getLatestArticleTimestamp`, `insertArticle`, `listHighImpactEventsInWindow`, `listHighMediumEventsInWindow` — **0 callers**.
- **Dangerously Divergent (Split Callers):**
  - **Alerts (`packages/db/src/queries/alerts.ts` vs `packages/ai/src/alerts/persistence/crud.ts`):** `apps/web` uses `@kestrel/ai`'s `createAlert` (which validates `AlertRuleSchema.parse`, `AlertChannelSchema.parse`, and clamps `snoozeHours` to `0..168`). `plugins/telegram-bot/src/bot/commands/alerts.ts:19` imports `createAlert` from `@kestrel/db`, which inserts `input.rule` (`unknown`) with **zero Zod validation**!
  - **Journal (`packages/db/src/queries/journal.ts` vs `packages/ai/src/journal/persistence/crud.ts`):** `@kestrel/db`'s `deleteJournalEntry` soft-deletes (`SET deleted_at = now()`) while `@kestrel/ai`'s `deleteEntry` hard-deletes (`DELETE FROM journal_entries`) and `@kestrel/ai`'s `listEntries` does **not** filter `isNull(deletedAt)`! Meanwhile `plugins/paper-trading/src/services/journal-sync.ts:19` calls `createJournalEntry` from `@kestrel/db`, which skips the `rememberJournalEntry` RAG embedding hook!
  - **Threads (`packages/db/src/queries/threads.ts` vs `packages/ai/src/persistence/thread-persistence/`):** `@kestrel/db` exports `deleteThread`, `appendUserMessage`, `appendAssistantMessage` with the exact same names as `@kestrel/ai/persistence`, but `@kestrel/db`'s `deleteThread` skips Mastra vector/working-memory cleanup (`cleanupDeletedThreadMemory`) and its `appendUserMessage` lacks idempotency keys!

### 3.3 Triple Tool System & XAUUSD PoC Duplication in `@kestrel/ai`

- **3 Tool Suites:**
  1. `packages/ai/src/tools/*` (21 legacy AI SDK tools wrapped at runtime via `adaptLegacyReadOnlyTool`).
  2. `packages/ai/src/mastra-v2/tools/canonical/*` (7 native Mastra tools: `price`, `candles`, `indicators`, `market-structure`, `news`, `cot`, `knowledge`).
  3. `packages/ai/src/mastra-v2/agents/xauusd/tools/*` + `read-only-tools.ts` (19 XAUUSD-specific Mastra tools: `get-xauusd-price`, `get-xauusd-candles`, etc.).
- **Legacy PoC XAUUSD Route Split (`version: 'poc-5'`):**
  - When `symbol === 'XAUUSD'` in `single` mode, `execution-routes.ts` routes to `xauusd-conversation` or `xauusd-research` (`packages/ai/src/mastra-v2/agents/xauusd/`, 34+ files).
  - For all other 17 symbols (`EURUSD`, `BTCUSDT`, etc.), it routes to `symbol-research` (`packages/ai/src/committee/`) or `canonical-chat` (`packages/ai/src/mastra-v2/agents/canonical/`), which already support `ALL_SYMBOLS` (including `XAUUSD`)!
- **3 Copy-Pasted Web Chat Stream Services (`apps/web/src/lib/services/mastra/chat/`):**
  - `mastra-chat-stream.ts`, `mastra-canonical-chat-stream/service.ts`, and `mastra-custom-agent-stream/service.ts` duplicate the exact same ~120-line budget reservation, user message append, `while (liveToolEvents.length > 0)` async generator loop, title generation, and stream finalizer logic.

### 3.4 Duplicated Web Mutations & Cron/Worker Drift

- **Settings Server Actions vs REST Routes:**
  - `apps/web/src/app/(app)/settings/_actions-models.ts` (`updateChatModelAction`) duplicates `PUT /api/settings/chat-model` (`apps/web/src/app/api/settings/chat-model/route.ts`), **omitting** the API key ownership check, catalog membership check, and embedding-tier rejection check!
  - `apps/web/src/app/(app)/settings/_actions-preferences-symbols.ts` (`addSymbolAction`) duplicates `POST /api/settings/symbols` with 70 lines of raw inline SQL instead of calling `isSymbolInCatalog` and `addUserSymbol`.
  - 22 `_actions-*.ts` files form a 2-layer re-export pyramid flat inside `apps/web/src/app/(app)/settings/`.
- **Web Cron Routes (`apps/web/src/app/api/cron/*`) vs Worker Jobs (`apps/worker/src/jobs/*`):**
  - `briefings`, `weekly-review`, `fred-actuals`, `cot`, and `snapshots` are copy-pasted between `apps/web/src/app/api/cron/*` and `apps/worker/src/jobs/*`.
  - **Live Bug Found:** When R1 tenant scoping (`withUserTenant` / `getActiveUserIdsForCron` on admin DB) was added to `apps/web/src/app/api/cron/briefings/route.ts` and `weekly-review/route.ts`, the duplicate worker jobs (`apps/worker/src/jobs/briefings.ts` and `weekly-review.ts`) were **missed**! Under the non-bypass `kestrel_app` role, the worker's `briefings` and `weekly-review` jobs run unscoped and will silently read zero rows or fail RLS!
